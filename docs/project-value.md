# 项目价值说明

## 1. 项目定位

InsightFlow 是面向数据分析师和经营人员的智能经营分析 Agent。它把自然语言问数、业务知识检索和多步骤经营分析放在同一条可追溯链路中，重点解决“数据能查到，但分析过程需要人工串联”的问题。

项目属于“生产力 / 工作流”类应用，不是为了展示一个孤立的聊天机器人，而是让 Agent 完成从经营问题到证据、结论和建议的闭环。

## 2. 目标用户

| 用户 | 典型任务 | 当前平台对应能力 |
| --- | --- | --- |
| 数据分析师 | 查指标、拆维度、核对口径、制作经营图表 | 智能图表 Agent、SQL 安全校验、RAG 口径检索 |
| 运营与经营人员 | 解释销售、渠道、库存和售后变化 | 经营分析 Agent、多步骤工具调用、报告生成 |
| 数据产品 / 工程人员 | 接入新数据域并控制访问边界 | 数据目录、Gold 汇总表、表字段白名单、只读事务 |

## 3. 核心痛点

传统处理方式通常存在四个问题：

1. 用户需要知道表名、字段名和 SQL 写法，业务问题不能直接转成查询。
2. 不同数据域的指标口径容易混用，例如把天猫行为记录当成订单或销售额。
3. 数据查询、图表制作、知识检索、口径核对和报告撰写由人工在多个工具之间切换。
4. 结果缺少来源和过程，难以判断数字是否真实、口径是否正确。

## 4. Agent 解决流程

```text
经营问题
  → 意图理解与数据域识别
  → 数据资产和指标口径发现
  → 生成查询方案
  → AST 校验、表字段白名单、只读事务
  → 查询结果解释
  → 必要时检索业务知识并附来源
  → 自然语言智能图表
  → 多步骤经营分析与报告生成
```

其中，模型负责理解、规划和解释；确定性代码负责数据权限、安全校验、重试上限、结果契约和来源边界。

## 5. 可交付价值

| 价值 | 体现方式 | 证据位置 |
| --- | --- | --- |
| 降低问数门槛 | 用户用自然语言提问，不必直接编写 SQL | `backend/app/agent/data_query/` |
| 减少口径误读 | 天猫与零售数据域隔离，知识库提供指标定义和限制 | `backend/app/agent/data_query/catalog.py`、`backend/knowledge_seed/` |
| 缩短分析链路 | 经营分析 Agent 可调用图表查询、知识、指标和报告工具 | `backend/app/agent/business_analysis/` |
| 提升可追溯性 | 返回结构化结果、知识来源、SSE 过程和持久化报告 | `docs/architecture.md` |
| 控制 Agent 风险 | AST 校验、字段白名单、只读事务、超时和有限修复 | `backend/app/services/safe_query.py` |
| 降低复刻门槛 | Docker Compose、init 服务、Demo/Real 双模式 | `docker-compose.yml`、`scripts/bootstrap.ps1` |

## 6. 适合本赛道的理由

项目对应题目中“生产力 / 工作流”示例，而不是低价值的“上传文件后生成摘要”。它的核心价值在于：围绕真实经营目标，自动完成需求理解、数据查询、口径核对、知识检索、证据组织和行动建议，形成“问题 → 证据 → 分析 → 决策”的闭环。
