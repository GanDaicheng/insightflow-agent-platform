# 电商经营分析 Agent 仓库整理设计

## 目标

把仓库的公开主线收敛为“面向单个电商公司的经营分析 Agent”：默认 Demo 只使用合成电商经营数据和零售知识库，面试官无需下载 CSV 或天猫数据即可启动；同时把开发过程文件、历史数据域和展示文档从主目录中分离。

## 现状与约束

- 当前 Demo 初始化脚本已经只生成零售电商演示数据，并导入 `backend/knowledge_seed_demo/`。
- 天猫功能仍存在于模型、领域路由、指标目录、Demo 场景、导入脚本、知识文档、测试和 README。
- 工作区已经有未提交的智能问数和知识问答前端改动，必须保留，不做 reset 或覆盖。
- 不直接删除数据库卷中的数据，不改写已经发布的 Alembic 历史迁移。
- 真实模式仍需要用户自己的模型、Embedding 和可选 Reranker 配置；Demo 模式不需要这些 API Key。

## 设计决定

### 1. 默认产品主线只保留 retail

从运行时 Agent、Demo 场景、目录注册、知识入库说明和公共 README 中移除天猫领域。保留零售业务的订单、商品、渠道、促销、履约、库存、广告和售后能力。

### 2. 历史 Tmall 代码不参与默认运行

天猫旧模型、服务、导入脚本、知识文档和专属测试移动到 `legacy/tmall/` 归档区，不再被应用导入、默认初始化或默认测试发现。Alembic 中已经存在的迁移文件保留为历史记录，避免破坏已有数据库。

### 3. 面试启动路径必须不依赖外部数据下载

README 明确说明：`APP_MODE=demo` 会在 PostgreSQL 中生成合成电商数据；仓库不提交数据库文件，也不要求面试官下载原始数据。真实模式的差异只体现在模型 API Key。

### 4. 根目录只保留运行与面试必需内容

主目录保留 README、环境示例、Compose、依赖文件、`backend/`、`frontend/`、`docs/` 和 `scripts/`。`.claude`、`.superpowers`、本机编辑器配置和生成物不再作为 GitHub 主项目内容；流程图归入 `docs/assets/`。

## 验收标准

- README 不再把天猫作为项目能力或面试演示主线。
- 全新环境按 Demo 命令启动时，不需要下载任何数据文件，并能完成数据库初始化、后端 readiness 和前端启动。
- 默认应用代码、Demo 场景和知识种子不再引用 Tmall。
- 历史迁移不被删除或重写，已有数据库不被自动清空。
- 前端、后端和文档相关测试通过；Git diff 不包含工作区原有改动的回退。
