# 天猫 IJCAI 2015 数据集业务背景

> 文档类型：数据集背景说明
> 适用范围：天猫 IJCAI 2015 复购预测数据集（本地抽样副本）
> 使用对象：数据分析、智能问数 Agent、取数开发

## 1. 这是一份什么数据

这是一份**电商平台的行为日志抽样**，来自 IJCAI 2015 阿里移动推荐算法竞赛公开数据集，
覆盖 2014 年 5 月 11 日到 11 月 12 日、约半年的双十一前后窗口。

它由四个文件组成：

| 文件 | 内容 | 一行代表什么 |
| --- | --- | --- |
| `user_info` | 用户画像 | 一个用户的年龄段与性别编码 |
| `user_log` | 用户行为日志 | 一次行为记录（点击 / 加购 / 收藏 / 购买） |
| `train` | 复购训练样本 | 一个「用户 × 商家」样本，带真实标签 |
| `test` | 复购测试样本 | 一个「用户 × 商家」样本，**没有标签** |

本地保存的是**按用户抽样后的子集**（抽样方式见《抽样与数据质量》），
这一点在解释任何绝对数字时都必须说清楚：这里的「7712 个用户」不是平台用户总数，
而是抽样后进入本地的用户数。

## 2. 业务场景：双十一复购预测

这份数据集要解决的业务问题是：**给定一个用户在某个商家有过互动，
他未来会不会在这个商家再次购买？**

这个问题在电商里叫「复购预测」，双十一大促期间尤其关键——
大促的流量成本极高，把预算投给「已经发生过互动、并且大概率会再来」的人群，
回报远高于广撒网。

数据集把这个问题拆成了两部分：

- `train` 集给出历史样本与真实结果（`label` 为 1 表示确实复购了），
  用来训练和评估模型；
- `test` 集只给出样本，不给答案，用来做预测。

**注意：`test` 集在这一版数据里既没有真实标签，也没有预测概率。**
官方发布的 `test_format1.csv` 里 `prob` 列是整列为空的——那一列是留给参赛者
写预测结果的。所以本地无法用它评估任何模型的准确率，
只能做「用户 × 商家」这一层的样本量统计。

## 3. 时间窗口为什么重要

窗口是 2014-05-11 ~ 2014-11-12，正好横跨双十一。这意味着：

- 数据里**天然包含大促效应**：11 月的活跃度会明显高于 5~8 月，
  这不是「业务在增长」，而是大促带来的脉冲；
- 任何跨月对比都要意识到这一点。把 11 月和 6 月放在一起比，
  得到的是「大促 vs 平销」的差异，不是「用户变多了」；
- 只有半年，做不了同比——数据里没有 2013 年的对应窗口。

## 4. 行为日志的四条动作

日志里的 `action_type` 有四条取值，含义与顺序如下：

| 编码 | 名称 | 中文 | 业务含义 |
| --- | --- | --- | --- |
| 0 | `click` | 点击 | 用户查看了商品 |
| 1 | `cart` | 加购 | 用户把商品放进了购物车 |
| 2 | `buy` | 购买 | 用户购买了该商品 |
| 3 | `favorite` | 收藏 | 用户收藏了商品 |

这四条动作构成了一条**业务上说得通**的路径：看到 → 有意向 → 决定买。
但请注意措辞：是「业务上说得通」，不是「数据里能证明」。
数据里没有 session，无法还原某个用户在某一次访问里的真实动作顺序，
详见《指标口径》一节的说明。

## 5. 这份数据**没有**什么

这一点比「有什么」更需要记住，因为缺失的信息恰恰是最容易被凭空补上的：

| 缺失的信息 | 因此**不能**计算 |
| --- | --- |
| 商品价格、优惠、运费 | GMV、销售额、收入、利润 |
| 订单号 | 准确订单量、客单价、每单件数 |
| 购买数量 | 销量件数 |
| 商品名称、品牌名称 | 「卖得最好的商品是什么」这类需要具体名称的回答 |
| 商家名称、类目名称 | 「哪个商家/类目卖得好」的具体名称 |
| 地区、收货地址 | 地域分析、区域对比 |
| 物流、签收状态 | 履约分析 |
| 退款、退货 | 退款率、净销售额 |

数据里只有**整数 ID**：商品 ID、商家 ID、类目 ID、品牌 ID。
ID 可以排序、可以去重计数，但映射不到任何可读的名称。

任何以「销售额」「GMV」「客单价」形式给出的天猫答案都是编造的——
这份数据里没有任何一个字段能支撑它。同理，问「天猫的 GMV 是多少」
时正确的回应不是给一个数字，而是说明这份数据集不包含价格信息。

## 6. 与零售样例数仓的关系

本项目里同时存在两套数据：

| | 零售样例数仓 | 天猫 IJCAI 2015 |
| --- | --- | --- |
| 时间 | 2025 全年 | 2014 年 5~11 月 |
| 主体 | 客户 / 商品 / 区域 / 订单 | 匿名用户 / 商品 ID / 商家 ID |
| 有金额吗 | 有，精确到分 | **没有** |
| 有订单吗 | 有，订单号唯一 | **没有** |
| 能算 GMV 吗 | 能 | **不能** |

两套数据**不能关联查询**：时间不重叠、主体不重叠、口径也不通用。
把 `orders` 和 `tmall_user_metrics` 连在一起，SQL 能跑通、会返回数字，
但那个数字既不是零售的销售额，也不是天猫的转化率——它没有任何业务含义。
系统在资产检索与 SQL 校验两处都禁止了这种关联。
